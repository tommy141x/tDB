Prerequisites: a FiveM server on Windows or Linux x86-64,
[tLib](https://github.com/tommy141x/tLib/releases) **v1.0 or later** `ensure`d before tDB,
and no other database resource running — see [Replace oxmysql](#replace-oxmysql).

<Steps>

### Install tLib

Extract the [tLib release zip](https://github.com/tommy141x/tLib/releases) into
`resources/`. tDB fails to start without it.

### Extract tDB

Put the folder in `resources/` and keep the name `tDB`. A rename breaks the `@tDB/...`
paths other resources use.

<Callout type="warning" title="Transfer the zip, then unzip on the server">
  FTP clients in ASCII mode corrupt the PocketBase binary and the WebAssembly transpiler
  without changing their size. Move the `.zip` across and unzip it there, or use SFTP in
  binary mode.
</Callout>

### Add it to server.cfg

tDB must start before anything that queries the database.

```txt title="server.cfg"
ensure tLib
ensure tDB
```

### Start the server

On first start tDB creates a superuser and writes the credentials into `config.local.lua`.

**Copy the superuser password out of that first startup box.** It is shown once, on the run
that generates it, and redacted afterwards. It is also in `config.local.lua`, which is
gitignored and must stay that way. To pin your own login instead, set
`tdb_superuser_email` and `tdb_superuser_password` in `server.cfg` — see
[Configuration](/docs/tDB/configuration#where-a-credential-comes-from).

You are done when the startup box reports the database ready and prints an admin URL. If it
says **Waiting for tLib's HTTP listener**, that is not an error — see
[the admin UI](/docs/tDB/configuration#the-admin-ui).

</Steps>

## The admin panel in a browser, if you want it

**Optional. tDB is fully working without it** — queries, migrations and every export run
over the server, and no port is involved.

What a port buys is reaching the admin panel from a browser, at
`http://<your server>:7777/db/_/`. Leave it closed and the database is unaffected.
PocketBase's own port is internal and is never the one to forward.

Both settings are **tLib's**, not tDB's — there is no port in tDB's config:

```txt title="server.cfg — above ensure tLib"
set tlib_http_port 7777
set tlib_http_public_url "http://your-server-address:7777"
```

`tlib_http_port` is the port to open and forward on your host. `tlib_http_public_url`
is the address tLib tells browsers to use, and it is the one worth setting deliberately:
left unset, tLib detects your public IP, which is wrong whenever players reach the panel
by hostname or through a proxy. The symptom is not an obvious one — the panel loads and
then requests from it are refused — so if you reach the panel by anything other than a
bare IP, set it to exactly the scheme, host and port you type in the browser.

tLib prints the address it settled on at boot and says whether it was detected, so check
that line rather than guessing. The full reference is
[tLib's convars](https://timmygstudios.com/docs/tLib/convars#web).

## Replace oxmysql

1. Remove `oxmysql` from `server.cfg`. tDB answers the `oxmysql`, `mysql-async` and
   `ghmattimysql` export names too, so `exports.oxmysql:...` resolves to tDB with no script
   edits.
2. Change any file reference: `server_script '@oxmysql/lib/MySQL.lua'` becomes
   `server_script '@tDB/lib/MySQL.lua'`. Scripts that only call `exports.oxmysql` need no
   change.
3. If a script ships a `.sql` dump, drop it in `tDB/sql/` rather than loading it by hand —
   see [Importing `.sql` files](/docs/tDB/sql-imports).

<Callout type="danger" title="Don't run tDB and oxmysql together">
  They answer the same export name and point at two different databases. Remove one.
</Callout>

## Working from a git clone

A release download contains the PocketBase binary; a source checkout does not, so fetch it
once:

```bash
bun scripts/fetch-runtime.ts          # this platform
bun scripts/fetch-runtime.ts --all    # both, for building a release
```

Change `PB_VERSION` at the top of that script to move to a different release.

## Optional: help us fix tDB

tDB does not report its own faults to us. When it throws on your server the
error sits in your console, and unless someone opens a ticket we never learn it
happened — which means the bugs nobody reports are the ones that stay.

One line opts in, in `server.cfg` above `ensure tLib`:

```txt title="server.cfg"
set tlib_telemetry 1
```

That sends errors, warnings, renderer crashes and slow-operation outliers from
our own code. **No IP, no licence key, no server name, no player names or
identifiers**, and `<resource>_diag` output is never included. `tlib_telemetry_status`
in the console shows what is on and what decided it.

It is off unless you set it, nothing is gated behind it, and
[Diagnostics](/docs/tLib/telemetry) is the full account of what is and is not sent.
