tDB exposes PocketBase itself under `exports.tDB`. Use it or ignore it — the oxmysql surface
does not depend on any of it. Full signatures are on the
[API reference](/docs/tDB/api-reference); this page shows the shapes you will write.

## Wait for startup first

An early call parks until the database answers rather than failing, but it does not return
until then, and until the superuser session is up it can throw
`PocketBase client not ready yet`.

```lua
exports.tDB:onReady(function()
    local players = exports.tDB:getFullList('players')
end)

-- or
if exports.tDB:isReady() then ... end
exports.tDB:awaitConnection()
```

## Records

```lua
local player = exports.tDB:create('players', { username = 'John', score = 100 })
local one    = exports.tDB:getOne('players', recordId)
local page   = exports.tDB:getList('players', 1, 50)   -- .totalItems, .page, .totalPages
local all    = exports.tDB:getFullList('players', { sort = '-score' })
exports.tDB:update('players', recordId, { score = 150 })
exports.tDB:delete('players', recordId)
```

<Callout type="warning" title="getOne and getFirstListItem throw on a miss">
  They raise a 404 rather than returning `nil`. Wrap them in `pcall` when the record may not
  exist, or use a list call and check for an empty result.
</Callout>

Build filters with `filter()` so values are bound rather than interpolated:

```lua
local f     = exports.tDB:filter('score > {:min} && banned = {:banned}', { min = 100, banned = false })
local top   = exports.tDB:getFullList('players', { filter = f })
local first = exports.tDB:getFirstListItem('players', f)

local some  = exports.tDB:findRecordsByIds('players', { 'id1', 'id2' })
local n     = exports.tDB:countRecords('players', 'active = true')
```

## Collections

```lua
exports.tDB:createCollection({
    name = 'players',
    type = 'base',
    fields = {
        { name = 'username', type = 'text', required = true },
        { name = 'score',    type = 'number' },
        { name = 'banned',   type = 'bool' },
    },
})

exports.tDB:getCollections()
exports.tDB:updateCollection('players', { ... })
exports.tDB:deleteCollection('players')
exports.tDB:truncateCollection('logs')
```

## Realtime

Subscribe, then handle the event tDB emits. These are **server-local events**, so
`AddEventHandler` is the correct listener and the name is
`pocketbase:<collection>:<topic>`.

```lua
exports.tDB:subscribe('bans', '*')

AddEventHandler('pocketbase:bans:*', function(data)
    -- data.action is "create" | "update" | "delete"
    if data.action == 'create' then print(data.record.id) end
end)

exports.tDB:unsubscribe('bans', '*')
```

Custom topics, and broadcasting to them:

```lua
exports.tDB:subscribeToTopic('server_events')
AddEventHandler('pocketbase:topic:server_events', function(data) end)

exports.tDB:sendRealtimeMessage('server_events', { type = 'announcement', message = '...' })
local clients = exports.tDB:getRealtimeClients()

exports.tDB:unsubscribeFromTopic('server_events')
exports.tDB:unsubscribeByPrefix('server_')
```

<Callout type="info" title="RegisterNetEvent also works, but says the wrong thing">
  tDB never sends these over the network. `RegisterNetEvent` registers a local handler too,
  so an older example using it still runs — but it also advertises the event to clients for
  no reason. Use `AddEventHandler`.
</Callout>

## Record transactions and batches

`runTransaction` runs inside a real database transaction and returns one result per
operation:

```lua
local results = exports.tDB:runTransaction({
    { type = 'create', collection = 'players', data = { name = 'John' } },
    { type = 'update', collection = 'stats', id = statId, data = { total = 100 } },
    { type = 'delete', collection = 'temp',  id = tempId },
})
```

Batches are the PocketBase batch API instead, and must be enabled in
**Admin → Settings → Batch API**:

```lua
local batch = exports.tDB:batch()
batch = exports.tDB:batchCreate(batch, 'players', { username = 'Alice' })
batch = exports.tDB:batchUpdate(batch, 'players', playerId, { score = 100 })
local out = exports.tDB:batchSend(batch)
```

## Raw SQL

The same database the oxmysql exports use, with `{:name}` placeholders and no MySQL
translation. Write SQLite here.

```lua
local row   = exports.tDB:sqlSingle('SELECT * FROM players WHERE id = {:id}', { id = 1 })
local total = exports.tDB:sqlScalar('SELECT COUNT(*) FROM players')
local newId = exports.tDB:sqlExecute('INSERT INTO logs (msg) VALUES ({:m})', { m = 'hello' })

exports.tDB:sqlTransaction({
    { sql = 'UPDATE accounts SET balance = balance - {:n} WHERE id = {:a}', params = { n = 100, a = 'a' } },
    { sql = 'UPDATE accounts SET balance = balance + {:n} WHERE id = {:b}', params = { n = 100, b = 'b' } },
})
```

Result shapes are discovered from the database, so `SELECT *` returns the table's real
columns, integers arrive as numbers, and `NULL` arrives as `nil` rather than an empty
string. `sqlExecute` returns the insert id only.

## Users, files and mail

```lua
local result = exports.tDB:authWithPassword('users', email, password)
exports.tDB:requestPasswordReset('users', email)
exports.tDB:confirmPasswordReset('users', token, new, newConfirm)
exports.tDB:authWithOAuth2Code('users', 'google', code, verifier, redirect)

local url   = exports.tDB:getFileUrl(record, 'avatar.png')
local token = exports.tDB:getFileToken()

exports.tDB:sendEmail('user@example.com', 'Welcome', '<h1>Hi</h1>', 'Hi')
```

`sendEmail` needs mail configured in the admin UI — see
[Mail](/docs/tDB/configuration#mail).

## The admin UI

On by default and needs no configuration. tDB claims the `/db` route on tLib, which holds
the server's single external port, so the admin UI appears at
`http://<your server>:7777/db/` and the panel itself at `/db/_/`. Sign in with
`Config.Superuser`.

There are no tDB host, port or mount settings. PocketBase binds `127.0.0.1:8090`, or any
free port if 8090 is taken, and tells tLib's router which one it got. That port is internal:
it does not belong in your firewall, and forwarding it would expose the database directly.
The only port you ever set is tLib's, with `set tlib_http_port`. For a completely headless
database, set
`Config.ExposeAdmin = false`.

### The mount follows tLib

It is re-claimed whenever tLib's listener comes up, not once at startup:

- tLib not ready yet → the box says **Waiting for tLib's HTTP listener**, not "mount
  failed". The mount is claimed and the URL logged as soon as tLib reports ready.
- tLib stops or restarts → tDB stops advertising the admin URL and re-claims on return.
- Route health is checked against tLib's own listener, not the public URL, so a reverse
  proxy or unreachable public address does not show as a failure.
- tLib too old to report HTTP readiness → the admin UI is not published at all and the box
  tells you to update tLib. `Config.ExposeAdmin` is left exactly as you set it.

The database is unaffected in every one of these cases: every oxmysql export and the whole
query path go over loopback and never touch tLib's router.
